# 训练数据筛选与均衡方案

> 版本：2026-08-18<br>
> 适用阶段：Wan2.2-TI2V-5B LoRA smoke、pilot 与 scale<br>
> 核心目标：在不过度放大低质量小数据集的前提下，让模型均衡学习人—物、人—人、第一人称、全身动作和状态变化。

## 1. 决策摘要

训练集不应按数据集等量抽样，而应按“任务能力 × 视角 × 运动强度 × 场景”分层，在每一层内部优先选择高质量样本，并限制单一来源的最大占比。

本项目采用以下顺序：

1. 先执行文件、解码、镜头连续性、caption 和数据泄漏等硬过滤。
2. 对此前生成的 caption 做复核和分级，仅重做不确定或错误部分，不重新 caption 全量数据。
3. 以任务类别作为主要均衡轴，数据集来源只作为上限约束。
4. 使用质量分数与采样权重保留多样性，不把筛选简单理解为“只留下最高分”。
5. 先冻结约 4 万条 Gold Pilot；通过固定验证后，再扩展到约 11.8 万条 Silver Scale。

所有原始记录继续保留在总 manifest 中。筛选结果通过 `eligible`、`quality_tier`、`sampling_weight` 和 `reject_reason` 表达，避免更改阈值时重复处理原始数据。

## 2. 筛选流水线

```text
原始视频与 caption
        |
        v
硬性可用性检查 ----失败----> 保留记录，eligible=false + reject_reason
        |
        v
Caption 三帧复核 ----C 级----> 简化、重做或暂缓
        |
        v
任务/视角/运动标签
        |
        v
去重与 source_sequence_id 分组
        |
        v
质量评分 + 分层配额 + 采样权重
        |
        v
按原始序列隔离 train / val，冻结 manifest 与 SHA-256
```

筛选分为三类操作：

| 操作 | 目的 | 是否永久删除 |
|---|---|---|
| 硬过滤 | 排除无法训练或明确错误的数据 | 否，只标记不可用 |
| 软评分 | 区分高质量与可接受样本 | 否，影响层级和权重 |
| 分层均衡 | 控制任务、来源和视角分布 | 否，决定当前实验是否入选 |

## 3. 硬性可用性过滤

### 3.1 视频与文件

以下条件任一成立时，设置 `eligible=false`：

- 路径不存在、不能完整解码或无法提取首帧。
- 按当前 49 帧训练窗口采样后帧数不足。
- 大面积黑屏、纯文字页、损坏帧或连续重复帧占比过高。
- 单个训练窗口内存在明显剪辑、场景跳变或拼接视频。
- 短边低于 480，或放大到目标尺寸后主体已经不可辨认。
- 水印、字幕条或 UI 长期覆盖主体和交互区域。

亮度、清晰度和运动幅度不使用统一的全局绝对阈值。先按来源计算分布，再人工查看每个来源的分位点；默认只淘汰该来源技术质量最差的 5%–10%。这可以避免 EasyCom、VFHQ 等低运动但任务相关的数据被整体误删。

### 3.2 Caption

以下情况直接拒绝：

- 空 caption、文件名、`video_id` 或数据集 ID。
- `A person performing a daily activity` 等通用模板。
- 主体、动作或物体与视频明显矛盾。
- 只描述静态外观，完全没有动作或状态变化。
- 同一来源内完全相同的 caption 出现超过 4 次；超出部分暂缓。
- 过长且包含大量不可验证细节、人物身份推断或幻觉。

### 3.3 去重与数据泄漏

采用三层去重：

1. 文件哈希发现完全重复。
2. 首、中、末帧感知哈希发现转码、裁剪或分辨率不同的近重复。
3. 视频 embedding 聚类发现同一动作的高度相似切片；建议从余弦相似度 0.96 开始校准。

完全重复只保留技术质量最高的一条。动作相同但视角或结果不同的样本可以保留，但同一 duplicate cluster 的总采样权重应归一化。

所有来自同一原始视频、同一对话或同一动作序列的 clips 必须拥有相同 `source_sequence_id`，并整体进入 train 或 val，禁止跨 split。

## 4. Caption 复核与再利用

### 4.1 不重新生成全量 Caption

保留两个字段：

- `caption_raw`：此前模型生成的原始结果，永不覆盖。
- `caption_train`：清洗、简化或复核后实际用于训练的文本。

主训练 caption 统一使用一种语言。若当前绝大多数 caption 为英文，则 `caption_train` 统一为英文，中文翻译可作为辅助元数据保留，但不随机混入训练 prompt。

推荐结构：

```text
主体及初始状态 -> 动作的时间进展 -> 动作结果/交互对象 -> 必要的镜头运动
```

推荐：

```text
A man stands beside a table. He reaches for a red cup,
lifts it with his right hand, and places it near the sink.
```

拒绝：

```text
The video shows a person performing a daily activity.
```

### 4.2 三帧复核

对每条 caption 同时输入首帧、中间帧和末帧，让复核模型判断：

1. 主体是否存在且保持一致。
2. 动作是否真的发生。
3. 物体、方向、颜色和数量是否有依据。
4. 动作结果是否能从末帧观察到。
5. 是否错误地把镜头运动描述为人物运动。

复核结果分三级：

| 等级 | 定义 | 处理 |
|---|---|---|
| A | 主体、动作、对象和时间顺序均有画面依据 | 直接进入 Gold 候选池 |
| B | 主要动作正确，但部分细节不确定 | 删除不确定细节后进入 Silver/Gold 候选池 |
| C | 动作错误、模板化或幻觉严重 | 重新 caption 或 `eligible=false` |

推荐长度为约 8–50 tokens。过长 caption 优先简化，而不是直接丢弃。删除 `the video shows`、文件名和数据集名称等无信息前缀。

### 4.3 当前 Caption 的具体处理

- 仓库当前跟踪的 Charades、EasyCom、RAVDESS 示例 metadata 含通用模板，不能直接进入 Gold Pilot。
- 如果共享存储或 Hugging Face 上已有更新后的完整 caption manifest，应先执行三帧分层抽查，再替换示例 metadata。
- CelebV-HQ 在 caption 覆盖和复核通过前暂缓。
- MIRA 等大规模来源只抽取动作明确、镜头连续的高置信样本，避免凭数量主导训练。
- 不必重做所有 A 级 caption；把计算预算集中在 B/C 级和稀缺任务类别。

## 5. 均衡目标

### 5.1 主要任务分布

每条样本只设置一个 `task_primary`，其他属性通过多标签字段记录。Pilot 推荐范围：

| `task_primary` | 推荐比例 | 主要候选来源 |
|---|---:|---|
| `hand_object` 手部—物体操作 | 25%–30% | HOIGen、DexYCB、H2O、Ego-Exo4D |
| `social_interaction` 社交、轮次、目光和手势 | 20%–25% | NoXi、EasyCom、Direct |
| `body_motion` 全身动作与移动 | 15%–20% | Charades、Ego-Exo4D、MIRA |
| `egocentric_navigation` 第一人称导航和视角变化 | 10%–15% | Ego-Exo4D、Direct、H2O |
| `face_head_gaze` 面部、头部与近景行为 | 10%–15% | VFHQ、RAVDESS、NoXi |
| `open_environment` 开放场景和环境状态变化 | 5%–10% | MIRA、Charades、Direct |
| `synthetic_replay` 游戏/合成高动态 replay | 5%–10% | Matrix、经复核的 MIRA 子集 |

比例是目标区间，不是要求每个 batch 精确满足。数据量不足的任务先建立下限，不通过复制低质量样本来填满配额。

### 5.2 交叉属性约束

- Pilot 中单一来源不超过 25%；scale 中最多 30%。
- 真实人物数据不少于 90%，游戏/合成 replay 不超过 10%。
- 第一人称约 25%–35%，第三人称约 55%–65%，近景人脸约 10%–15%。
- 低/中/高运动幅度目标约为 20%/55%/25%。低运动样本用于目光、手势、轮次和面部行为，不应全部删除。
- 横屏与竖屏分别建 bucket；首轮 1280×704 pilot 不随机混入 704×1280 样本。
- 记录室内/室外、单人/双人/多人、光照和相机运动分布，用于发现偏差，但首轮不强制每一维完全均匀。

## 6. 质量评分与采样权重

硬过滤通过后，为每条样本计算归一化到 `[0, 1]` 的质量分数：

```text
quality_score =
    0.25 * technical_quality
  + 0.30 * caption_grounding
  + 0.25 * temporal_dynamics
  + 0.20 * task_relevance
```

建议分层：

- `gold`：`quality_score >= 0.80` 且 caption 为 A 级。
- `silver`：`quality_score >= 0.65` 且 caption 至少为清洗后的 B 级。
- `hold`：低于 0.65，或仍需要复核，不进入当前训练。

阈值必须在每个来源至少人工抽查 50–100 条后校准，不能在没有人工样本的情况下直接作为最终标准。

为了避免高质量的大数据集完全覆盖稀缺任务，训练采样权重建议为：

```text
sampling_weight =
    quality_score^2
  * sqrt(median_task_count / task_count)
  * (median_source_count / source_count)^0.25
```

将最终权重裁剪到 `[0.25, 4.0]`。任务类别使用较强的平方根补偿，来源只使用较弱的四次方根补偿，从而兼顾任务均衡，又不把很小但噪声较高的数据集过度重复采样。

## 7. Manifest 字段

建议在丰富版 JSONL 中加入以下字段；DiffSynth 使用的 `video,prompt` CSV 继续由丰富 manifest 导出：

```json
{
  "video_path": "dataset/wan22_training/example.mp4",
  "caption_raw": "...",
  "caption_train": "...",
  "caption_grade": "A",
  "caption_review_model": "...",
  "caption_review_version": "...",
  "source_dataset": "hoigen1m",
  "source_sequence_id": "hoigen1m:sequence-001",
  "duplicate_cluster_id": "dup-000001",
  "task_primary": "hand_object",
  "task_tags": ["reach", "grasp", "place"],
  "viewpoint": "egocentric",
  "human_count": 1,
  "motion_level": "medium",
  "camera_motion": "handheld",
  "technical_quality": 0.91,
  "caption_grounding": 0.88,
  "temporal_dynamics": 0.84,
  "task_relevance": 0.95,
  "quality_score": 0.89,

```

自动标签、评分模型、prompt 模板和阈值必须保存版本号。否则重新运行后无法解释数据分布变化。

## 8. 数据冻结与验收

### 8.1 分阶段规模

1. **Calibration**：按来源和任务分层人工抽查约 1,000 条，用于校准阈值。
2. **Smoke**：256 条候选，验证完整训练链路。
3. **Gold Pilot**：约 40,000 条，以 A 级 caption 和 gold 样本为主。
4. **Silver Scale**：约 118,000 条；仅在 pilot 通过模型评估门槛后构建。
5. **Reserve**：保留失败类型和困难样本，用于后续 hard-example mining，不直接加入首轮训练。

### 8.2 冻结门槛

- 选中路径存在率 100%。
- Smoke 全量、Pilot 随机 500 条的解码与首帧提取成功率 100%。
- 空 caption、模板 caption、重复视频和跨 split 序列泄漏均为 0。
- 每个任务达到最低比例；单一来源不超过阶段上限。
- 每个来源抽查至少 50 条，每个主任务抽查至少 50 条。
- 保存 config、输入 manifest、输出 manifest、代码 commit 和 SHA-256。
- 验证集冻结后，后续基座、LoRA 和消融实验不得重新抽样。

人工抽查报告至少记录：Caption 正确率、动作时间顺序正确率、主体/物体幻觉率、镜头剪辑率、近重复率和每类拒绝原因。

## 9. 与仓库代码的关系

当前代码已经覆盖第一阶段可复现基础设施：

- `scripts/build_unified_manifest.py`：确定性来源配额、caption 模板/长度/精确重复过滤、按序列切分和哈希冻结。
- `scripts/audit_experiment_manifest.py`：字段、路径、caption、来源占比和 split 泄漏审计。
- `scripts/decode_audit.py`：随机解码与首帧提取审计。
- `training_metadata/experiment_sources.example.json`：smoke、pilot、scale 的来源配额。

下一轮代码应按以下顺序扩展，避免一次性引入难以校准的自动评分：

1. `enrich_manifest.py`：计算视频技术指标、任务/视角/运动标签。
2. `caption_critic.py`：首/中/末三帧复核，输出 A/B/C 和简化 caption。
3. `deduplicate_manifest.py`：文件哈希、帧感知哈希与 embedding 聚类。
4. 扩展 `build_unified_manifest.py`：支持 `quality_tier`、任务配额和 `sampling_weight`。
5. 生成 HTML/CSV 数据卡，显示来源、任务、caption 等级和拒绝原因分布。

在自动标签和评分代码完成前，首轮 Gold Pilot 可以先使用来源配额、模板过滤、序列隔离和分层人工抽查冻结；不要让尚未实现的自动评分阻塞 E0/E1 smoke。

## 10. Go / Revise / Stop

- **Go**：数据门槛全部通过；人工抽查 Caption A/B 合格率至少 95%；任务和来源分布满足约束；进入 Pilot。
- **Revise**：技术可用但某些任务、来源或 Caption 等级偏差明显；调整配额、简化 Caption 或局部重做。
- **Stop**：存在路径/解码问题、明显跨 split 泄漏、模板 Caption 大量漏入或数据快照不可复现；停止训练并重新冻结。

Pilot 训练后还应按失败类别回流：手部变形、人物身份漂移、动作未完成、物体状态错误、相机运动异常分别对应不同的数据补充或降权策略。不要只根据 diffusion loss 扩量。
