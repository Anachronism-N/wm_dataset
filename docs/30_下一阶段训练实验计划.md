# 下一阶段训练实验计划

> 版本：2026-08-18<br>
> 适用模型：Wan2.2-TI2V-5B + DiffSynth-Studio LoRA<br>
> 决策目标：先证明“高质量人类交互数据能稳定改善 TI2V 动作与状态变化”，再扩大数据量或进入流式 Student。

数据硬过滤、既有 caption 复核、任务分层均衡、质量评分和采样权重的详细规则见 [训练数据筛选与均衡方案](31_训练数据筛选与均衡方案.md)。

## 1. 结论先行

当前不需要等待 383 万 clips 全部 caption 完成。约 169 万 clips 已有 caption，其中除 MIRA 外，HOIGen、Charades、NoXi、VFHQ、Direct、Ego-Exo4D、Matrix、EasyCom、DexYCB、H2O 等已经提供足够的高质量候选池。建议立即冻结 256 条 smoke 和约 4.08 万条 landscape pilot，先完成基座对照、训练稳定性和动作结果一致性验证。

本轮必须避免三件事：

1. 不把尚未 caption 的 CelebV-HQ 128 万 clips 混入训练。
2. 不把 704×1280 的竖屏数据与 1280×704 横屏 pilot 混在固定分辨率 batch 中。
3. 不再使用仓库中旧的 `combined_metadata.csv`、`charades_metadata.csv` 等模板 caption 文件；其中包含 `video_id`，不能作为训练文本。

## 2. 仓库目标与当前阶段

项目目标是构建“多模态大脑 + 视频 DiT 渲染器”的全双工交互世界模型。大脑负责理解意图、维护人物/物体/场景状态并生成交互计划；渲染器根据文本、首帧、历史视频、动作和记忆生成连续反馈。当前 Wan2.2-TI2V-5B LoRA 是非流式 Teacher 的第一阶段验证，不是最终流式系统。

截至仓库提交 `e329f763350c5bdff208c306c4b3ea3d9089337e`：

| 指标 | 当前状态 | 训练含义 |
|---|---:|---|
| 已处理数据集 | 14 个 | 预处理不再是首要阻塞 |
| 已处理 clips | 约 383 万 | 总量远超首轮需要 |
| 已 caption | 约 169 万（44%） | 可训练池足够，但分布不均 |
| CelebV-HQ caption | 0 / 1,277,996 | 暂不进入训练 |
| MIRA caption | 1,216,449 / 2,073,297 | 只作小比例动态/游戏 replay |
| HF 上传 | 73 shards 已完成，HOIGen 24/61 | 训练节点优先读共享存储；上传不是 smoke 前置条件 |
| Issue / PR | 0 / 0 | 进度与缺口主要存在于文档，不在任务跟踪系统中 |

此前“caption 59.6%”与现在“44%”并不矛盾：前者使用较小的阶段性分母，后者加入 CelebV-HQ 等新数据后以约 383 万 clips 为分母。实验应使用冻结 manifest 的实际统计，不再引用滚动分母判断可训练性。

## 3. 已识别的工程缺口与本轮修复

仓库文档曾引用 `train_wan22.sh`、`smoke_test_wan22.sh`、训练 config 和 64–256 条 smoke manifest，但当前 `main` 分支此前没有这些文件。原 `build_unified_manifest.py` 和 `decode_audit.py` 还硬编码了集群路径，原始 CSV 中存在空/模板 caption。

本轮新增或修复：

- `scripts/build_unified_manifest.py`：JSON 配置驱动；按源序列切分；稳定采样；caption 长度、模板和精确重复过滤；输入/输出 SHA-256 冻结。
- `scripts/audit_experiment_manifest.py`：检查必填字段、空/短 caption、`video_id`、重复视频、来源占比、文件存在性和 train/val 源序列泄漏。
- `training_metadata/experiment_sources.example.json`：给出 smoke、pilot、scale 三档横屏配比；CelebV-HQ 和竖屏数据默认禁用。
- `scripts/train_wan22.sh`：对齐 DiffSynth-Studio 官方 Wan2.2-TI2V-5B LoRA 参数；锁定已核验提交；自动计算 smoke repeat；W&B 默认关闭。
- `scripts/decode_audit.py`：移除固定集群路径，支持 CSV/JSONL、相对路径和跨平台临时目录。

当前官方 DiffSynth-Studio 使用统一 `video,prompt` metadata，Wan 系列训练入口为 `examples/wanvideo/model_training/train.py`；官方 TI2V LoRA 示例使用 rank 32、学习率 `1e-4`、49 帧、`--extra_inputs input_image`，训练模块会从 `data["video"][0]` 构造首帧条件。参考：[Wan 模型训练说明](https://github.com/modelscope/DiffSynth-Studio/blob/main/docs/en/Model_Details/Wan.md)、[官方 Wan2.2-TI2V-5B LoRA 脚本](https://github.com/modelscope/DiffSynth-Studio/blob/main/examples/wanvideo/model_training/lora/Wan2.2-TI2V-5B.sh)。本轮核验的 DiffSynth-Studio 提交为 `89ceaa660b936cd065373ee1f33527ed215f64dd`。

## 4. 数据冻结方案

### 4.1 Smoke：256 条候选，约 90% 训练 / 10% 验证

| 来源 | 候选数 | 目的 |
|---|---:|---|
| HOIGen | 48 | 手物交互主干 |
| Ego-Exo4D | 40 | 第一/第三人称动作 |
| Charades | 32 | 日常动作组合 |
| NoXi | 32 | 双人互动 |
| Direct / Project Aria | 24 | 第一人称活动 |
| VFHQ | 24 | 人脸与上半身保持 |
| Matrix | 16 | 复杂相机/运动 |
| MIRA | 16 | 高动态 replay |
| EasyCom | 12 | 多人对话场景 |
| DexYCB | 8 | 精细抓取 |
| H2O | 4 | 双手第一人称操作 |
| 合计 | 256 | 单一来源不超过 30% |

### 4.2 Pilot：约 40,797 条候选

| 来源 | 候选数 | 占比（约） |
|---|---:|---:|
| HOIGen | 10,000 | 24.5% |
| Ego-Exo4D | 6,000 | 14.7% |
| Charades | 6,000 | 14.7% |
| NoXi | 5,000 | 12.3% |
| Direct / Project Aria | 4,000 | 9.8% |
| VFHQ | 3,000 | 7.4% |
| Matrix | 2,000 | 4.9% |
| MIRA | 2,000 | 4.9% |
| EasyCom | 1,500 | 3.7% |
| DexYCB | 1,000 | 2.5% |
| H2O | 297 | 0.7% |

该配比将真实人物、人-物、人-人和第一人称数据置于主导地位，游戏数据约 10%，用于保留动态与相机运动能力。横屏 pilot 通过后，再单独训练/评估 704×1280 竖屏桶。

### 4.3 数据验收门槛

- 选中视频路径存在率 100%。
- 随机 500 条可解码率和首帧提取率均为 100%。
- 空 caption、`video_id`/文件名 caption、跨 split 源序列泄漏均为 0。
- 精确重复 caption 每个来源最多 4 条；单一来源不超过 30%。
- 训练/验证输出、输入 manifest 和配置均保存 SHA-256。
- 验证集冻结后，所有基座/LoRA/消融使用同一批首帧、prompt、seed 和推理参数。

## 5. 实验顺序与停止门槛

### E0：基座冻结评估（训练前）

从 pilot validation 中固定 128–256 组首帧 + prompt，覆盖手物、人物动作、双人互动、第一人称和复杂运动。每组至少 4 个固定 seed，保存 Wan2.2 基座输出。没有 E0 就不能判断 LoRA 是否真正改善。

### E1：Smoke LoRA

| 项 | 设置 |
|---|---|
| 输入 | `unified_smoke_train.csv` |
| 分辨率 | 832×480（只验证闭环） |
| 帧数 | 49 |
| LoRA | rank 32，targets `q,k,v,o,ffn.0,ffn.2` |
| 学习率 | `1e-4` |
| 目标更新数 | 约 200，脚本按进程数自动计算 repeat |
| 保存 | 每 100 steps |

通过条件：训练无 OOM/NaN/持续 loader 错误；checkpoint 可加载和继续；固定样例可生成；TI2V 首帧条件确实生效。任一条件不满足则停止，不进入 pilot。

### E2：Landscape Pilot LoRA

| 项 | 设置 |
|---|---|
| 输入 | 约 4.08 万候选，约 90% 训练 |
| 分辨率 | 1280×704 |
| 帧数 | 49 |
| LoRA / 学习率 | rank 32 / `1e-4` |
| epoch | 1 |
| 保存 | 每 500 steps；保留中间 checkpoint |

每个 checkpoint 对 E0 的固定集合生成结果。DiffSynth-Studio 官方说明指出扩散 loss 与视觉效果相关性有限，因此不能只按 loss 选 checkpoint，应以固定验证生成和盲评为主。参考：[DiffSynth-Studio 模型训练说明](https://github.com/modelscope/DiffSynth-Studio/blob/main/docs/en/Pipeline_Usage/Model_Training.md)。

### E3：最小必要消融

1. **Human-only vs. +10% game replay**：总样本数、steps、seed 相同；判断 MIRA/Matrix 是否改善动态而损害真人动作/身份。
2. **原生/模板 caption vs. 简洁 VLM caption**：在同一 10K 子集上对照；判断 caption 质量而非数据量的贡献。
3. **rank 16 vs. 32**：仅在 E2 明显过拟合或 checkpoint 体积/吞吐成为问题时执行，不作为首轮必跑项。

### E4：Scale

只有 E2/E3 达到 go 条件后，扩到约 11.8 万横屏样本；再评估是否加入已完成 caption 的更多 MIRA、CelebV-HQ 和竖屏数据。不要直接从 4 万跳到全部 169 万，更不要混入无 caption 数据。

## 6. 评估协议

### 自动与工程指标

- 生成成功率、黑帧/冻结帧/解码失败率。
- 首帧主体与场景保持：DINO/CLIP 图像相似度或 LPIPS，按来源报告分布。
- 动态质量：motion smoothness、temporal flicker、dynamic degree。
- 文本/动作一致性：VBench 相关维度 + VLM judge，但 VLM judge 只作辅助。
- 数据来源切片：手物、第一人称、双人互动、人脸、游戏分别报告，禁止只看总均值。

### 人工盲评

在 100 组固定样例上比较 base 与 LoRA，每组随机左右呈现，至少 3 名评审，记录：

1. 动作/交互是否按 prompt 完成。
2. 人物、手、物体和场景是否保持。
3. 动作后的物体/人物状态是否合理。
4. 是否出现严重闪烁、形变、冻结或镜头异常。

E2 的建议 go 门槛：动作完成偏好率相对 base 至少 55%；首帧主体保持指标下降不超过 3 个百分点；严重伪影率不高于 base 2 个百分点。未达到门槛时优先回查 caption、数据配比和 checkpoint，而不是立即扩量。

## 8. 一周节奏

| 时间 | 任务 | 交付物 / 决策 |
|---|---|---|
| Day 1 | 冻结 smoke/pilot；路径、caption、泄漏、解码审计 | manifest + report + SHA-256 |
| Day 1–2 | E0 基座固定评估；E1 smoke | 基座视频、可恢复 smoke checkpoint |
| Day 2–4 | E2 pilot；每 500 steps 固定推理 | checkpoint 曲线与样例 |
| Day 4–5 | base vs LoRA 自动指标和盲评 | go / revise / stop |
| Day 5–7 | E3 两个核心消融 | 数据配比与 caption 结论 |
| 下一周 | 仅在通过门槛后 E4 scale；竖屏另桶 | 规模化 checkpoint / 竖屏决策 |
